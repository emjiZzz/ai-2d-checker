# ADR-014 — Consult the ground truth after the comparison, and never grade yourself on what you studied

**Status:** proposed · **Date:** 2026-09-07 · **Rung 3** of [[ADR-007 Re-scoping the Maturity Ladder]]

---

## Context

The owner stated the shape directly:

> compare two drawings -> look up for patterns on ground truth -> ask itself if it compares the
> data correctly or if the data being compared was in the ground truth -> perfect comparison

This is not a new direction. [[ADR-007 Re-scoping the Maturity Ladder]] already defines rung 3 as
*stored human decisions move output, measured*, and names the learned-dismissal flywheel and the
learned overlay as its substrate. What changes is the source and the scope.

Three things are now true that were not when rung 3 was written:

1. **The seam exists.** `apply_learned_adjustments` already runs after every comparison, on the
   fresh path (`orchestrator.py:300`) and on the cache-hit path (`:140`), so a retrain takes
   effect without invalidating the cache. It is bounded: `SPATIAL_CATEGORIES` only, and it only
   flips `CHANGED`/`ADDED`/`REMOVED` toward `MATCHED` below `LOW_THRESH`.

2. **The old source could not do half the job.** `audit_feedback` requires `original_status`,
   "Status generated by AI engine", and all seven correction verbs are overrides of a finding the
   engine produced. It structurally cannot contain a miss. See
   [[Gotcha - The Ground Truth Store the RAG Could Not Read]].

3. **The right source is now indexed.** `ground_truth` became a retrieval collection on
   2026-09-07, carrying the pattern (category, feature, entity type, layer, the observed change,
   the engineer's verdict and note) and the location (coordinates, handle, layer, drawing, room).

The corpus is empty. This ADR decides the shape before collection starts, because one of the
decisions below cannot be applied retroactively.

---

## Decision

### 1. The pass runs after the comparison, never inside it

`generate_deterministic_candidates` stays a pure function of the two drawings, making no retrieval
call and no database call. The verification pass consumes its output.

The reason is attribution, which in this repo is the product. The rule that outranks the rest is
that a refactor must be proven inert before anything is attributed to it; retrieval reaching into
the engine makes every future measurement ambiguous between "the engine changed" and "the corpus
changed". Keeping it downstream also means the existing offline eval seam keeps working unchanged,
and the pass can be measured by running the corpus with it on and off.

### 2. Two checks, named separately, measured separately

The owner's "ask itself" is two questions that move different numbers in opposite directions:

| | Verification | Omission |
| :--- | :--- | :--- |
| Asks | of a reported finding, have humans seen this pattern and rejected it | of a human marking, did the engine report it |
| Moves | precision | recall |
| Failure | suppresses a real finding | floods the checklist with false alarms |

They are separate stages with separate metrics. A single combined "self-check" number can improve
precision while destroying recall and read as progress; that is the exact failure the per-category
scorer exists to prevent, reintroduced one layer up.

**Omission is the valuable half.** The headline gap in this system is that false negatives have
never been measured, and every prior mechanism — the learned overlay, the dismissal rules,
`audit_feedback` — could only ever act on findings the engine already produced.

### 3. What is retrieved from must be disjoint from what is measured on

**This is the decision that cannot be applied retroactively, and the reason this ADR is written
before collection rather than after.**

A pass that consults ground truth derived from the same pair it is scoring will score near-perfect
and mean nothing: it is being graded on the answer key it studied. Held-out pairs must therefore
never enter the retrieval index, and the index must be able to state which pairs it was built
from.

Stage 0b already requires 3 held-out pairs and has 1. A held-out pair must be exported before any
comparison has run on it, and prototype mode cannot run one, so prototype mode is the only way to
produce them. Set them aside during collection, not after.

Enforced rather than reviewed: a test asserts no held-out pair id reaches
`rebuild_ground_truth_index`.

### 4. Explicit code decides first. The LLM does not decide

[[ADR-010 Grounded LLM Summarization of Comparison Results]] stands unamended: the model
summarizes findings and never decides them. The first implementation is thresholds over retrieved
neighbours — "N engineers marked this pattern NOT_A_FINDING in this category, so downgrade" — for
the same reason `params.py` exists: a constant declared in one place can be swept and attributed,
and a judgement inside a model cannot.

A learned or generative judge is a later question and needs its own ADR, including whether
ADR-010's rule is being amended.

### 5. Off by default until measured on held-out human pairs

The pass ships behind a flag, defaulting off, until it has a recorded delta on held-out human
pairs — precision and recall separately, per category. A rung 3 claim needs `rung_evidence`; a
flag that is on by default with no measurement is a rung claim with no evidence link, which the
ledger defines as a defect.

### 6. Every adjustment names the markings that caused it

A suppression or an omission alert records which ground-truth records produced it. The safe-zone
net in `zone_ownership.py` is the precedent: anything it drops is logged, so the upstream bug stays
findable. An unattributable suppression is indistinguishable from an engine bug, and it fails in
the false-negative direction.

---

## Consequences

- Recall becomes addressable for the first time. Nothing before this could represent a miss.
- Two more numbers to maintain, and they must be quoted together. Precision alone will look good
  the moment suppression is switched on.
- The corpus gains the power to suppress real findings. Blast radius is bounded the way the
  learned overlay bounds it — by category — and every drop is attributable per decision 6.
- Collection discipline is now load-bearing. Pairs set aside as held-out are worth more than pairs
  labelled, because there are 8 registered and only 1 held out, and labelling cannot produce more.
- The eval harness needs an on/off switch for the pass, so its effect is measured rather than
  assumed. `tools/eval.py` already has the shape for this in `--no-templates`.

---

## Alternatives rejected

**Retrieval inside the comparison engine.** Reads as the more integrated design and destroys
attribution: no future measurement could separate an engine change from a corpus change. It also
breaks the offline eval seam, which makes no database call by construction.

**One combined self-check score.** Simpler to report and hides the trade it is making. Precision
and recall move in opposite directions here.

**An LLM as the judge, now.** ADR-010 forbids it for findings, and at this corpus size a
per-decision judgement could not be attributed to anything. Revisit with an ADR, not in passing.

**`audit_feedback` as the retrieval source.** Structurally cannot contain a miss, so it can only
sharpen what the engine already sees. This is what the system did until 2026-09-07.

**Building it now.** The corpus is empty. Everything here is measurable only once markings exist,
and a threshold tuned on nothing is a constant nobody can defend.

---

## Deliberately not decided

- **Similarity.** Lexical against the existing TF-IDF index, or learned. `retrieval/encoder.py` is
  a seam so this can be a bake-off rather than an assumption.
- **What an omission does.** Auto-report as a finding, or surface as "possible miss" for the
  checker to accept. The second is safer and costs a click; no evidence yet says which is right.
- **Cross-sheet generalisation.** Whether a pattern marked on one sheet may fire on another, or
  only within the same sheet family. This is where a suppression rule becomes dangerous, and the
  `AutoDocEngine` cross-client defect is the precedent for getting it wrong.
- **Threshold values.** They are a sweep, once there is something to sweep on.

---

## What moves this to accepted

A measured delta on held-out human pairs with the pass on and off, precision and recall reported
per category, and the held-out disjointness test green. Until then this records the shape and the
trap, not a result.
