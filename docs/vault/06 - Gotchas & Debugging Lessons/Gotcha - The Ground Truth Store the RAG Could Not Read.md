# Gotcha - The Ground Truth Store the RAG Could Not Read

> Found 2026-09-07, from an owner sentence: *"we already created prototype mode so human checks
> will be the basis of the RAG."* They were not. `ALL_COLLECTIONS` had seven entries and
> `ground_truth_markings` was not one of them.

## The shape of it

Two stores hold a human's judgement, and they are not interchangeable:

| | `audit_feedback` | `ground_truth_markings` |
| :--- | :--- | :--- |
| Written from | AI-mode review of engine output | prototype-mode Manual Check |
| Anchored to | a finding the engine produced | the drawing itself |
| Can contain a false negative | **no** | **yes** |
| Indexed for retrieval before 2026-09-07 | yes, as `corrections` | **no** |

The asymmetry is structural, not incidental. `AuditFeedbackDocument` requires `original_status`,
described in its own schema as *"Status generated by AI engine"*, and all seven correction verbs
(`dismissed`, `confirmed_valid`, `category_override`, `verdict_matched`, `verdict_changed`,
`confirmed_change`, `value_correction`) are overrides of a finding the engine produced. There is
no verb for *"you missed this"*. So `audit_feedback` is a map of the inside of the engine's recall
boundary, drawn by a human standing inside it.

A Manual Check marking is made with the engine disabled -- `config/features.ts` forces every room
to a manual check in a prototype build, so `START COMPARISON` is unreachable -- which is why it is
the only store that can contain something the engine never reported, and therefore the only one
that can measure recall.

The system had been indexing the first and not the second. A retrieval layer fed only by
engine-anchored collections can learn the engine's blind spots back to itself and nothing else.

## Why the pools stay separate rather than merged

Merging `ground_truth` into `corrections` would let a row meaning *"the engine said this and the
engineer dismissed it"* answer a question about what is on the sheet. The blind spot returns
through the retrieval path instead of the training path, which is harder to see because retrieval
has no training run to inspect. Pinned by `tests/test_retrieval_ground_truth_pool.py`.

The corollary is that `audit_feedback` is not junk and should not be deleted for being
engine-anchored: the learned verdict head only ever sees engine candidates at inference
(`inference._decide` judges engine output), so human-reacting-to-engine rows are its matched
deployment distribution. Two stores, two jobs.

## What the repeat passes measured

The same pair was marked up four times across four re-uploads, which was done to test the upload
flow and turned out to be the project's first intra-annotator agreement measurement:

- pairwise self-agreement 0.84 - 0.97 (Jaccard)
- 27 of 32 findings appear in all four passes; 5 do not

The five that moved are not sloppiness. Each lands on an ambiguity found independently elsewhere:
`カラ－` categorised `title_block` in three passes and `drawing_views` in one; `%%c55-15` ->
`%%c55×15` statused CHANGED in three and MATCHED in one, the same cell the 2026-09-01 work-log
entry flagged for classifying two ways; and a bare `1` in a BOM row numbered 1, which is the
[[Gotcha - A Short Structured Value Suppresses Its Own Zone]] shape.

Two consequences:

1. A single-pair recall difference under roughly 10% is inside labelling noise. Every recall
   figure in [[00 - AI Maturity Status]] has been read as though the labels were exact.
2. A marking's status must reach the indexed *text*, not only its metadata. Two passes reaching
   opposite statuses on one string are byte-identical otherwise, and
   `_collapse_duplicate_texts` keeps one -- silently discarding the most informative row.
   Same rule and same reason as `feedback_record`'s verb.

## The three survivors a delete leaves behind

Removing the two collections is cosmetic on its own. The deprecated judgement keeps acting from:

1. `storage/retrieval/corrections/` -- a built index, 84 records, still served after the source
   rows are gone.
2. `services/backend/storage/models/finding_classifier.joblib` -- trained on 140 verdict labels,
   still flipping candidates to MATCHED below `LOW_THRESH`.
3. `docs/vault/08 - Client Domain & CAD Rules/Learned_Rules_General.md` -- 8 suppression rules
   promoted from dismissals, read at runtime by `vault_sync.get_learned_dismissal_rules()`, and
   also baked into the `domain_rules` index. That directory is gitignored, so the file is not
   recoverable from git.

All three are suppression, which is the false-negative direction, in the system whose headline
gap is that false negatives have never been measured.
